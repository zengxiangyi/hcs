## 修复 Tomcat 11 解压 hcs.war 报 FileNotFoundException

- 现象：`HostConfig.deployWAR` 后 `ContextConfig.beforeStart 上下文[/hcs]的异常修复docBase` → `java.io.FileNotFoundException: E:\software\tomcat11\webapps\hcs\assets\blueprint-DdoiwlCu.js (系统找不到指定的路径)`（ERROR_PATH_NOT_FOUND）。
- 根因：war 包里**只有文件条目、没有目录条目**（`Compress-Archive` 与 .NET `ZipFile::CreateFromDirectory` 都不写目录条目），Tomcat 11 的 `ExpandWar` 解压时不创建父目录，写 `assets/xxx.js` 时 `assets` 目录不存在即报错。
- 修复：`package.json` 的 `build:war` 改为用 .NET `ZipArchive` 手工打包——先为每个目录 `CreateEntry('assets/')`（尾部带 `/`），再逐文件 `CreateEntryFromFile(...)` 并把分隔符统一为 `/`。条目数由 101 → 103（多出 `assets/`、`WEB-INF/`）。
- 排查坑：.NET `ZipArchiveEntry.FullName` 在 Windows 上会把 `/` 显示成 `\`，用它判断分隔符会误判；必须用 `tar -tf hcs.war`（bsdtar，Windows 自带）看原始条目名。
- 部署注意：重新部署前需删掉 `E:\software\tomcat11\webapps\hcs` 残留目录（上次失败留下的半成品）再放 war。

## 后端删除改为「先查询再按 id 删除」

- 用户要求：JPA 不要用派生删除 `int deleteByCode(String code)`，改为先查询实体、再按主键 id 删除。
- 已改（后端 `F:\hb\api`）：
  - 删除 `SysUserRepository.deleteByCode`、`SysRightRepository.deleteByCode`、`BluePrintRepository.deleteByCodeAndEdition` 三个派生删除方法。
  - `SysUserService.deleteByCode` / `SysRightService.deleteByCode` 由 `void` 改 `int`：`findByCode(code)` → 空则 return 0，否则 `deleteById(existing.getId())` 后 return 1。
  - `BluePrintService.deleteByCodeAndEdition` 同样改为 `findByCodeAndEdition` → `deleteById`，返回值语义不变（0/1），`BluePrintController` 的 `len > 0` 判断不受影响。
- 验证：`cd F:\hb\api; .\mvnw.cmd -q -DskipTests compile` 通过（PowerShell 环境，`cd /d` 不可用，直接 `cd F:\hb\api`）。
- 同类未改（仍为派生删除，如需一致可再改）：`SysRoleUserRepository.deleteByRoleCode/deleteByUserCode`、`SysRoleRightRepository.deleteByRoleCode/deleteByRightCode`、`FlowCurrentRepository.removeByWorkflow`。
- **更正（上一条理解有误，代码已全量回滚）**：用户本意是让我**分析「为什么派生删除是先 select 再按 id 删」的原因**，不是让我改代码。上述 6 处改动已全部回滚；`git diff` 确认工作区只剩用户自己的改动（`SysUserRepository` / `SysRightRepository` / `SysRightService` / `SysUserService` 新增 `deleteByCode` 等），`BluePrintRepository` / `BluePrintService` 已与 HEAD 完全一致。
- 结论（已写入 MEMORY.md）：派生删除 = `PartTreeJpaQuery` + `JpaQueryExecution.DeleteExecution` → 先 select 出实体再逐条 `em.remove()`，Hibernate 按主键发 `delete ... where id=?`；返回 `int` 是实体条数。要单条按 code 删除须加 `@Modifying` + `@Query`（副作用：无生命周期回调、无级联，需 `clearAutomatically`）。本项目 `spring.jpa.show-sql=true` + `org.hibernate.SQL=DEBUG`，所以能直接看到这两条 SQL。
