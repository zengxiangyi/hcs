## 技术答疑：Vue SFC 中定义的内容如何跨组件复用
- 结论：`.vue` 的 `<script setup>` 是独立 ES Module 且**禁止写 export**，内部定义的函数/变量/类型默认无法被其他组件 import，需抽离为 `.ts` 才能复用（语法上可再加一个普通 `<script>` 块 export，但会连带编译模板/样式，不推荐；`defineExpose` 仅父子 ref 调用，非模块级复用）。
- 分类决策：纯函数/常量 → `utils/*.ts`；类型 → 就近 `types.ts` 或 `src/types/*.ts`；模块级单例状态 → 独立 `.ts`（如 `components/sys/permission.ts`）；带响应式逻辑 → `composables/useXxx.ts`；全局业务状态 → Pinia；仅单组件使用 → 留在 `.vue`。判断标准：被 ≥2 个 `.vue` 用到才抽。
- 项目现状：`utils/enum.ts`、`components/sys/permission.ts`、`components/tech/plan/types.ts` 已是正确范式（7 处 import）。**缺口：无 `src/composables/`、无 `src/types/`**；`ApiResponse` 现定义在 `api/http.ts`，作为全局契约更适合迁到 `src/types/api.ts`。分页/加载态逻辑疑似各 `.vue` 复制粘贴，建议抽 `useTable.ts`。
