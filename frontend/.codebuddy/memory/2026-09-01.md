## 技术答疑：Vue SFC 中定义的内容如何跨组件复用
- 结论：`.vue` 的 `<script setup>` 是独立 ES Module 且**禁止写 export**，内部定义的函数/变量/类型默认无法被其他组件 import，需抽离为 `.ts` 才能复用（语法上可再加一个普通 `<script>` 块 export，但会连带编译模板/样式，不推荐；`defineExpose` 仅父子 ref 调用，非模块级复用）。
- 分类决策：纯函数/常量 → `utils/*.ts`；类型 → 就近 `types.ts` 或 `src/types/*.ts`；模块级单例状态 → 独立 `.ts`（如 `components/sys/permission.ts`）；带响应式逻辑 → `composables/useXxx.ts`；全局业务状态 → Pinia；仅单组件使用 → 留在 `.vue`。判断标准：被 ≥2 个 `.vue` 用到才抽。
- 项目现状：`utils/enum.ts`、`components/sys/permission.ts`、`components/tech/plan/types.ts` 已是正确范式（7 处 import）。**缺口：无 `src/composables/`、无 `src/types/`**；`ApiResponse` 现定义在 `api/http.ts`，作为全局契约更适合迁到 `src/types/api.ts`。分页/加载态逻辑疑似各 `.vue` 复制粘贴，建议抽 `useTable.ts`。

## 架构咨询：前后端一体化 Vibe Coding 方案
- 用户诉求：前端（本项目）与后端（../backend）分两个项目分别开发，希望降低沟通成本，评估"一体化 Vibe Coding"可行性。
- 现状盘点（实证）：
  - 前端 `src/api/` 共 15 个模块（auth/blueprint/constValue/flow/instance/process/right/role/roleRight/roleUser/taskProcess/tech/transfer/user 等），后端 `src/routes/` 仅 `auth.ts`、`users.ts` —— 前端大量接口后端尚未实现，属"前端按约定路径先行"。
  - `docs/api.md` 明确记录"接口端点为前端约定路径，若后端实际路径不同需调整"，即前端在猜后端，是主要浪费点。
  - 后端技术栈 Fastify 5 + Drizzle ORM + mysql2/MySQL，端口 8080，响应契约 `{code,data,msg}`，`src/db/schema.ts` 已有 Drizzle 表定义但无对外 schema/契约产物。
  - 前后端各自维护 `CODEBUDDY.md` + `docs/`，且**两端都有 `openspec/` 目录但 specs 与 changes 均为空**（仅 config.yaml）。
- 给出的方案主线：不合并工程，改为「契约先行 + 单一事实源 + 上下文共享」四层架构（契约层 / 仓库组织 / AI 上下文工程 / 验证闭环），以 OpenAPI(code-first, @fastify/swagger) + msw mock + OpenSpec 变更流程 + 契约漂移 CI 为抓手，npm workspaces 建 `page/contract/` 共享目录。

## 追问：前端 agent 直接读取后端代码一起分析修改，是否可行
- 结论：**只读完全可行且推荐**（backend 就在同级 `../backend`，agent 已实际跨目录读取过 CODEBUDDY.md / src 结构验证过）；**跨端写入需严格约束**。
- 关键判断（基于实证）：前端 15 个 api 模块 vs 后端 2 个路由，其中 13 个接口属**缺失**而非**不对齐** —— 读后端代码对这 13 个接口无解（后端压根没有实现），只能靠契约 + msw mock。读取能力解决"对齐问题"，解决不了"缺失问题"。
- 三种落地形态：A 只读挂载（起步，成本最低）/ B multi-root workspace（.codeworkspace 含 frontend+backend+contract，最一体化）/ C 双 agent team 协作（仅大改动，日常不必）。
- 主要风险：① 上下文稀释（禁止整目录灌入，按需精读）② 无契约层时 AI 会"照抄后端实现"从而固化后端错误 → 契约层必须优先于跨端读取 ③ 跨端写入冲突与授权问题（当前工作区为 frontend，改 backend 属工作区外操作，需显式授权）。
- 建议约定：`backend/` 默认**只读**，仅当用户显式要求时才改；根级 `CODEBUDDY.md` 声明该规则。
