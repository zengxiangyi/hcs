## 代码评审与安全加固（预生产发布条件）
对 `src/` 全部 10 个 TS 文件做了评审与完善。

### 关键契约（务必遵守，勿改）
- **密码「直存直比」**：前端登录/注册/重置密码提交的是 `md5(password)` 密文，后端 `accounts.password` 原样存储并直接比对。**后端不得对 body.password 二次 md5**（否则双重哈希导致登录永远失败）。`md5()` 仅在 seed.ts 用于 `md5('123456')` 生成初始密文。

### 已修复问题
1. **JWT_SECRET 强校验**：`index.ts` 启动前若缺 `JWT_SECRET` 直接 `process.exit(1)`，不再回退硬编码 `'dev-secret-change-me'`（避免 token 可被伪造）。
2. **CORS 收紧**：已**回退**。原因：部署/发布来源未知、白名单无法预置，强制白名单会导致联调与上线跨域失败。恢复为 `origin: true` + `credentials: true`（见 index.ts 注释）。待上线确定前端域名后再收紧为白名单。`.env.example` 中新增的 `NODE_ENV`/`CORS_ORIGINS` 也一并移除。
3. **路由参数校验**：`users.ts` 新增 `parseIdOr400()`，对 `/api/users/:id` 的 id 做整数/正数校验，非法返回 400，避免 NaN 进入 SQL。
4. **注册竞态**：`auth.ts` 注册改为依赖 `accounts.username` 的 `unique()` 约束原子插入（去掉先 select 再 insert 的非原子校验），唯一键冲突捕获为「用户名已存在」。

### 已知保留项（历史包袱，预生产需知悉）
- **md5 用途澄清**：本项目用 md5 是为**避免密码明文在 POST 请求中传输**（前端先 md5 再提交，后端直存直比），属传输层脱敏，非存储哈希强度方案。用户明确暂不升级 bcrypt/argon2。后续评审勿将其列为"待修复安全项"而擅自改动。
- `GET /api/user/info` 语义临时（返回表首条），属占位。
