## 修复：未带 token 请求返回 500（前端报错）
- 现象：`AuthenticationCredentialsNotFoundException` 抛在 `JwtAuthenticationFilter` → 前端只看到 500，axios 401 拦截器不生效（只在 `status===401` 时跳登录），页面直接报错。
- 根因：`addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter)` 使该过滤器**早于 `ExceptionTranslationFilter`**，抛出的 AuthenticationException 无人翻译成 401，冒泡到容器变 500。
- 改法：
  1. `SecurityConfig.unauthorizedEntryPoint` 从私有 lambda 字段改为 `@Bean`。
  2. `JwtAuthenticationFilter` 新增 `AuthenticationEntryPoint` 字段（三参构造器；为 null 退化为 `sendError(401)`），缺头/校验失败时**主动调用** `entryPoint.commence(...)` 而非 throw。
  3. `securityFilterChain` / `jwtAuthenticationFilter` 都用方法参数注入该 bean。
- 待验证：`./mvnw -o -q compile`（本次两次执行均被用户跳过，仅 read_lints 干净）。

## 修复：登录后跳回 /api/login?redirect=/
- 根因（node + vue-router 实测复现）：`f:/hb/page/frontend/src/router/index.ts` 中 `/` 与 `/login` **两条路由 name 都是 'Login'**。重名会让 vue-router 丢失先注册记录的 name → 守卫里 `to.name === undefined` → `WHITE_LIST.includes` 失效 → 无 token 时根路径被弹到 `{name:'Login',query:{redirect:'/'}}` → `/api/login?redirect=/`。
  - 实测对照：`[唯一name] root -> / name=Login` vs `[重复name] root -> /login?redirect=/`。
- 修法：`/` 路由改名 `Root`，`WHITE_LIST = ['Root','Login']`（保留 `/api/` 可直接访问/刷新的行为）。
- **vue-router 硬规则：路由 name 必须唯一，重名会静默破坏 name 相关判定（resolve by name、守卫白名单），且不报错。**
- 触发点补充：任何整页重载（F5，或 axios 401 拦截器 `window.location.href = BASE_URL`）都会重跑该流程，表现为「登录后又回登录页」。
- 前端产物 `src/main/resources/static` 仍是旧 bundle（含重名），**需 `npm run build` 后覆盖 dist 才生效**。
- 排查技巧：minified 产物可用 PowerShell `Select-String -Path x.js -Pattern '...' -AllMatches | ForEach-Object { $_.Line.Substring($_.Matches[0].Index-N, 300) }` 取上下文（注意同一行多匹配要遍历 `$_.Matches`）。

## 备查：当初的部署形态讨论（方案已定为 B）
- 现象「登录之后跳转被拦截」根因侧写：登录用 `router.push('/web')`（纯前端跳转，不发请求，不会被拦）；被拦的是 **history 模式下刷新/直接访问 `/api/web/xxx`** —— 浏览器导航不带 Authorization 头，该路径不在 `PUBLIC_PATHS`，被 `JwtAuthenticationFilter` 回 401 JSON。后端还缺 SPA fallback，即使放行也是 404。
- 根本矛盾：**前端 SPA 路由与 REST API 共用 context-path `/api`**，白名单与 404 fallback 都无法干净地写（fallback 会把 API 404 变成 HTML）。
- 给出三方案：A) Nginx 托管 dist + 反代 `/api`（推荐，同源零跨域、try_files 天然解决 SPA 刷新、后端可删 static 并收回白名单）；B) 同 Tomcat 两个 war（ROOT.war 静态 + 404→/index.html 的 3 行 web.xml，与 `/api` **同源**，无 CORS 问题）；C) 维持合体但前端 base 改 `/api/ui/` + 放行 `/ui/**` + 定向 fallback。
- 关键结论：同一 Tomcat 上不同 context（`/` 与 `/api`）**属同源**（origin 只看 scheme/host/port），localStorage 共享、axios 无需 CORS；只有拆到**不同端口/不同机且无反代**才真跨域，届时必须先修已知 CORS 缺陷（`HttpSecurity` 未调 `.cors(...)` → 带 Authorization 的 OPTIONS 预检被拦 401）。
- 止血备选：前端改 `createWebHashHistory()`，URL 变 `/api/#/web/...`，服务端永远只收到 `/api/`，零后端改动。
