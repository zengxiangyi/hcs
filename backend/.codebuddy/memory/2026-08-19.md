## TS18046 复发修复（08-19 追加）

- **根因**：Fastify v5 `setErrorHandler<TError = unknown>(...)` 泛型默认 `unknown`。重构（08-19 多 agent 评审）曾把 setErrorHandler 简化成直接读 `error.statusCode`，去掉了 08-17 的 `instanceof Error`/`'statusCode' in error` 收窄，导致 `error` 重新被 strict 推断为 `unknown`（57 行 `error.statusCode`、59 行 `error.message` 报 TS18046）。
- **修复**：不再用参数类型注解，改为显式泛型 `app.setErrorHandler<FastifyError>((error, request, reply) => {...})`（从 `fastify` 导入 `FastifyError`），一行修复且类型更精确（FastifyError 自带可选 `statusCode`、继承 `message`）。
- **验证**：IDE lint 0 错误。
- **教训**：Fastify v5 下 setErrorHandler 的 error 参数依赖显式类型（泛型或注解），任何「简化收窄」的改动都可能导致该错误复发；`npm run build` 输出该错误时 exitCode 仍为 0，需人工留意。

## 前端白屏排查与修复（08-19 追加）

- **现象**：浏览器访问 `http://127.0.0.1:5173/`（前端 Vite，Vue3+Vite+TS，位于 `f:\hb\page\frontend`）页面白屏/无法显示。
- **排查**：后端 8080（Fastify）监听正常 `0.0.0.0:8080`；前端 5173 的 `netstat` 仅显示 `[::1]:5173`（IPv6 回环），`fetch('http://127.0.0.1:5173/')` 返回 `ECONNREFUSED`。前后端代码、路由、schema、seed 静态检查均正常、无 lint 错误。
- **根因**：Vite dev server 默认 `server.host` 在部分 Windows 上只绑定 IPv6 `::1`，未监听 IPv4 `127.0.0.1`，导致用户以 `127.0.0.1` 访问时 TCP 连接被拒 → 白屏。
- **修复**：在 `f:\hb\page\frontend\vite.config.ts` 的 `server` 中显式添加 `host: '0.0.0.0'`（监听所有网络接口，含 IPv4/IPv6）。
- **注意**：配置改动需**重启前端 dev server**（终止旧 Vite 进程后重新 `npm run dev`）才能生效。
